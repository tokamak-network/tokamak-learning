## Improvement Recommendations

1. **Add a "distractor compilation check" to the validation pipeline**: For every code question, programmatically substitute each distractor into the blank and attempt compilation via `solc`. Any distractor that compiles AND produces semantically correct behavior must be flagged automatically. This would have caught gen-c3 (`Base`) and gen-c4 (`fallback`).

2. **Avoid questions where Solidity has multiple equivalent mechanisms**: `super` vs explicit parent name, `receive` vs `fallback`, `memory` vs `calldata`, `public` vs `external` — these are common sources of multiple-valid-answer bugs. Either design the surrounding code to make only one option valid, or avoid these topics for fill-in-the-blank format.

3. **Ensure distractors for concept questions are unambiguously false**: The flash loan question (gen-q2) had a distractor ("no collateral") that is factually true. Generation prompts should explicitly instruct: "All distractors must be factually incorrect statements, not merely less-correct alternatives."

4. **Validate question count**: The batch contained 9 questions instead of the expected 10 (missing gen-c1). Add a count assertion in the generation pipeline.

5. **For inheritance/special-function questions, add constraints that disambiguate**: For gen-c3, a multi-inheritance chain would make `super` uniquely correct. For gen-c4, pre-defining a `fallback` with different behavior would make `receive` uniquely correct. The generation prompt should include guidance on creating disambiguating context.
